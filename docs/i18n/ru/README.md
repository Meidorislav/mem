# MEM: Твой локальный технический оракул

**Перестань искать в интернете решения, которые ты уже однажды нашел.**

MEM — это «второй мозг» разработчика внутри терминала. Он индексирует твой технический опыт: сессии в консоли, фрагменты конфигов и заметки по проектам, делая их мгновенно доступными через локальный приватный ИИ.

---

## 🚀 Основные возможности

*   **`mem ask` (Магия)**: Поиск по твоему опыту на обычном языке. Спроси *«как я чинил 502 ошибку в nginx в прошлом году?»* и получи точную последовательность действий.
*   **`mem watch` (Минимум усилий)**: Записывай терминальную сессию. Реши проблему, а затем используй `mem remember`, чтобы превратить историю команд в готовую инструкцию.
*   **`mem save`**: Мгновенно сохраняй сниппеты, команды-однострочники или заметки по архитектуре.
*   **CLI-First**: Создан для тех, кто живет в терминале. Никакого переключения на тяжелые GUI-приложения.

## 🧠 В чем отличие?

### Смысл, а не просто слова
Обычные инструменты вроде `grep` бесполезны, если ты не помнишь точных слов. MEM использует **семантический поиск**: он понимает *намерение*. Запрос «деплой» легко найдет заметку с заголовком «Настройка сервера».

### Полная приватность
Всё остается на твоем устройстве. MEM использует **локальные векторные эмбеддинги** и **локальную языковую модель (LLM)**. Твой код и конфиги серверов никогда не попадут в облако.

---

## 🛠 Как работает ИИ

1.  **Эмбеддинги**: Твои данные преобразуются в многомерные векторы (математическое представление смысла) с помощью локальной модели.
2.  **Семантический поиск**: Когда ты задаешь вопрос, MEM находит в локальной базе самые близкие по смыслу «воспоминания».
3.  **Локальный синтез**: Локальная LLM анализирует найденный контекст и выдает краткий ответ, основанный исключительно на *твоем* опыте.

## ⚡ Практические примеры

### 1. Сложные команды инфраструктуры
```bash
# Сохраняем последовательность настройки
mem save "Настройка репликации Postgres" -c "apt install postgresql-15; sed -i 's/wal_level = replica/wal_level = logical/' /etc/postgresql/15/main/postgresql.conf"

# Находим через полгода
mem ask "как включить логическую репликацию?"
```

### 2. Команда «Я это точно забуду»
```bash
# Сохраняем хитрую комбинацию find/xargs
mem save "удалить все пустые папки" -c "find . -type d -empty -delete"

# Мгновенно вспоминаем
mem ask "как почистить пустые директории?"
```

### 3. Запись сессии отладки
```bash
# Записываем поток действий при фиксе бага
mem watch
# $ ssh production-server
# $ journalctl -u api-service -n 100
# $ systemctl restart api-service
mem remember "перезапуск api-сервиса на проде"

# Позже спрашиваем, как мы чинили падение
mem ask "как я фиксил падение api-сервиса?"
```

## 📦 Установка

Нужны: Go 1.26+, C-тулчейн (LanceDB подключается через cgo) и локально запущенная [Ollama](https://ollama.com).

```bash
ollama pull bge-m3             # эмбеддинги, многоязычные (обязательно)
ollama pull llama3.2           # ответы для `mem ask --answer` (опционально)

make build                     # при первом запуске скачает нативные библиотеки LanceDB
./mem --help
```

Данные хранятся в `~/.mem/` (`mem.db` — SQLite, `vectors/` — LanceDB, `sessions/` — записи `mem watch`); переменная `MEM_HOME` переносит их в другую папку, например для черновой базы.

Модель эмбеддингов по умолчанию — `bge-m3`: она понимает русский и английский в одном индексе. Англоязычные модели вроде `nomic-embed-text` хорошо работают с английскими заметками, но русские вопросы для них почти шум. Сменить модель: `mem reindex --model <имя>`.

MEM обращается к Ollama по адресу `127.0.0.1:11434` или туда, куда указывает `OLLAMA_HOST` (формат как у CLI `ollama`: `host`, `host:port`, `http(s)://host:port`). Если указать другую машину, заметки и запросы будут уходить на неё.

Если после обновления `mem ask` сообщает, что часть воспоминаний не проиндексирована с текущими настройками, один раз запусти `mem reindex`.

## 📖 Команды

| Команда | Что делает |
|---|---|
| `mem save "заголовок" -c "cmd" [-c ...] [-t тег] [-d "описание"] [--force]` | Сохранить команды/заметку. Точную копию существующего воспоминания (тот же заголовок и команды) не сохранит без `--force` |
| `mem ask "вопрос" [-n 5] [--min-score 0.42] [--answer] [--llm llama3.2]` | Гибридный поиск: смысловое сходство плюс точные ключевые слова (коды ошибок, флаги, имена сервисов). У результата показано сходство (0–1) и пометка `keyword`, если совпали слова; слабые смысловые совпадения скрываются (порог по умолчанию подобран под модель эмбеддингов; `--min-score 0` показывает всё). Без Ollama ищет только по ключевым словам. `--answer` дополнительно просит локальную LLM свести результаты в ответ |
| `mem watch [--shell bash\|zsh]` | Запустить записываемый сабшелл; все команды логируются до `exit` |
| `mem remember "заголовок" [-t тег] [-d "..."] [-n N]` | Превратить записанную сессию (или её последние N команд) в воспоминание. Работает и внутри записываемого шелла |
| `mem list [-t тег] [-n 20]` | Список последних воспоминаний |
| `mem show <id>` / `mem delete <id>...` | Посмотреть воспоминание или удалить одно или несколько |
| `mem edit <id> [--title ...] [-d ...] [-c ...] [-t ...]` | Изменить воспоминание флагами (`-c` / `-t` заменяют все команды / теги) или без флагов в `$EDITOR`. После правки оно переиндексируется |
| `mem reindex [--all] [--model имя]` | Проиндексировать сохранённое без Ollama, пересобрать индекс или сменить модель эмбеддингов |

Команды, начинающиеся с пробела, `mem watch` не записывает, если шелл исключает их из истории (`HISTCONTROL=ignorespace` в bash, `setopt HIST_IGNORE_SPACE` в zsh).

## 🏁 Быстрый старт

```bash
# Сохрани свою первую команду
mem save "список файлов по размеру" -c "ls -lhS"

# Спроси себя из прошлого
mem ask "как посмотреть большие файлы?"

ls -lhS # список файлов по размеру
```

**MEM растет вместе с тобой. Через неделю это просто блокнот. Через год — твой самый ценный актив.**
